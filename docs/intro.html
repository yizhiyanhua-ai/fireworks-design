核为什么要这么设计

ClaudeDesign 官方原文一句话点破:"即使是经验丰富的设计师也只能克制地探索——很少有时间做十几个方向。" 本工作流把这句洞察工程化。

⊗ 单路生成的问题

一个模型、一次输出,本质是"抽一次签"。它的品味、当下倾向、prompt 解读都锁死在那一版里,质量上限被方差卡住。

⊛ 多路 + 评审的价值

并行铺开多种独立美学,再让独立评审从不同维度打分、取最优、嫁接亮点——把分布的方差变成质量下限的保证。

①Brief · 提炼设计系统

先把模糊需求压成所有设计师共享的 brief + design tokens,杜绝"通用 brief 产出通用页面"。

输入
prompt + 可选 brand
产出
产品定位 · 目标 · 必要章节 · 设计令牌(字体配对 / 调色板 hex / 基调 / 参考气质) · 成功标准
注入到
之后每一个 agent 的 prompt —— 保证整条流水线品牌一致

②Diverge · 广度探索

这是质量的核心。每个 agent 走一种独立美学风格,完整产出自包含 HTML 文件。

Bold Editorial Swiss Minimal Vibrant Gradient Dark Premium Soft Organic Neo-Brutalist Glass Aurora Mono Tech

每个 agent 内部先自拟方案 → 自我批判一次 → 再产出,而非直接吐结果。

1 个 brief 同时扇出成 6 份独立成品 · 全部并行

③Judge · 评审面板

每个方向 × 6 个设计维度,独立打分(1–10)。~36 路并行,严禁互相看答案。

层级 排版 配色/对比 动效/交互 工程工艺 惊艳度

每条评审还必须给出最高杠杆的修复建议,直接喂给下一阶段。

评分矩阵 · 取均分最高者为基底,同时收集每条修复建议

④Synthesize · 融合升华

不做简单"选冠军"。读 Top3 方向的源码,以最强者为骨架,嫁接其余亮点,并修掉评委所有 flagged 问题。

Editorial 的层级 + Dark Premium 的氛围 + Gradient 的动效 → 一份明确超越任何单方向的 final.html。

⑤Refine · 对抗式打磨

"狠辣评审 → 精准修复"循环 2 轮,这是 ClaudeDesign "fine-grained controls" 的工程化。

每轮 critique 返回带严重度的 issue 列表,fix agent 必须处理所有 critical/major

⑥Polish · 终检出图

最后一道质量闸门,逐项核查并修:

响应式 375/768/1280 WCAG AA 对比 prefers-reduced-motion 语义化 + ARIA 无控制台报错 无残留占位

≡与 ClaudeDesign 原理对照

ClaudeDesign 官方原理本工作流对应实现
广度探索(铺开十几个方向)② Diverge · 6–8 路独立美学并行
最强视觉模型判断③ Judge · 6 维 × N 方向独立评审
提炼最佳 + 融合④ Synthesize · Top3 嫁接升华
细粒度控制反复打磨⑤ Refine · critique↔fix 循环
设计系统贯穿① Brief · design tokens 注入每个 agent
导出可交付 HTML⑥ Polish · QA 后写出 final.html

▶怎么调用

// 命名工作流,直接执行
Workflow({
  name: "fireworks-design",
  args: {
    prompt:    "AI 笔记应用落地页,隐私优先 + 秒级检索,面向独立开发者",
    outputDir: "/Volumes/ExtaData/newcode/design-output/ai-notes",  // 必须绝对路径
    variants:  6,       // 探索方向数(默认6,最多8)
    refineRounds: 2,    // 评审-修复轮数(默认2)
    brand:     "可选:品牌色 #7c3aed,字体 Inter"
  }
})
